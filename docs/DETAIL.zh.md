# 工作迁移

把一台电脑上的开发工作（**代码 + 数据 + 对话记录**）导出成一个包，
在任意电脑上导入，并按你指定的分组重新归档。**导入后对话可以继续使用。**

## 为什么需要它

DSH 里一个「开发工作」分散在两处：

- **代码 / 数据** 在某个工作目录
- **对话记录** 在 `%USERPROFILE%\.dsh\sessions\...`

把工作目录搬走或改名后，对话里的路径还指着旧地方，打开会话就报错，
或者**点开没内容**。本插件负责把这些地方一起改对。

## 导出

侧边栏底部「⇅ 迁移」→ **导出**：

1. 勾选要导出的工作（可多选）
2. 填写保存路径（如 `D:\Harness Record\导出.dsht`）
3. 点「开始导出」

产物是一个 `.dsht` 文件（zip 格式），内含代码、数据、对话记录。

**安全保证**：`.credentials.yaml`、token、secret、`id_rsa`、`.env` 一律不打包。
`node_modules` / `.venv` / `__pycache__` 等可重建目录默认跳过。

导出**不修改任何数据**，DSH 开着也能用。

## 导入

侧边栏底部「⇅ 迁移」→ **导入**：

1. 填写 `.dsht` 包路径，点「读取」
2. 界面列出包内每个工作，**逐个指定归属**：
   - 保持原分组
   - 归到本机某个现有分组
   - **+ 新建分组…**（填分组名和父目录，**文件夹会自动创建**）
   - 跳过
3. 点「开始导入」

### 导入时会发生什么

点击导入后，插件会：

1. 生成迁移计划
2. 启动一个**脱离 DSH 生命周期**的后台进程
3. 提示你关闭 DeepSeek Harness

你关闭 DSH 后，后台进程自动完成：

- 全量备份（sessions + 投影缓存 + workspace.json）
- 复制工作目录到目标位置
- 改写对话的 `header.cwd`（严格按 2 帧结构，不改历史内容）
- 把对话目录搬到对应的新位置
- 更新工作区的路径与归属
- 新建分组文件夹
- **重新启动 DSH**

任一环节失败会自动全量回滚，并在 `storages\work-migrator\` 留下日志。

## 关于重启

**导入必须重启 DSH 才能生效。** 这是 DSH 的机制限制，不是插件的缺陷：

DSH 正在运行时会在内存里持有会话状态，写回磁盘时会覆盖外部修改。
所以真正写数据的动作必须在 DSH 关闭后进行。

插件把这一步做成了自动的：你只需要关掉 DSH，剩下的它自己完成，
包括最后帮你重新打开 DSH。

## 已知限制

- 导入的对话框里，包路径需要**手动输入完整路径**。
  DSH 目前只提供「选择目录」，没有「选择文件」的对话框。
- 导入过程中请不要手动修改工作目录或会话文件。
- 单个包超过 4 GB 时不支持。
- 在 Windows 上开发和测试，其他平台未验证。

## 技术说明

- 会话日志是**多帧 zstd**，读取需逐帧解压
- 写回时严格保持「首帧仅含 header 一行，其余每行以换行结尾」
- 修改前校验帧结构，修改后回读比对行数与内容

## 安装

```sh
dsh plugin --profile <profile> add @iridensity_gray/dsh-work-migrator
```

安装后重启 DSH。
